REGRAS GERAIS PARA GERAÇÃO DE CÓDIGO

IDIOMA

Todo o código de ser escrito em inglês, incluindo nomes de variáveis, funções e comentários; As únicas exceções permitidas são: nomes próprios e nomes ja existentes em outro idioma;

COMENTÁRIOS

O código sempre deve ser bem comentado, porém nao excessivamente, visando explicar o fluxo do que está  acontecendo, de aneira que alguém de fora do projeto consiga entender claramente;

Toda função deve ter um comentário descrevendo o que ela faz, embora o  comentário descritivo sempre seja necessário, nem sempre precisa adicionar no comentário descrições para parâmetros e tipagem, a depender da complexidade da logica daa função e dos dados tratados;

PROGRAMAÇÃO FUNCIONAL

Sempre que aplicável e sem criar overengineering, tenda a aplicar o paradigma da programação funcional, criando e dividindo fluxos em funções menores, puras, que executam apenas uma tarefa;

ALTERAÇÕES

Quando código ja existente for alterado, não gere o código todo, toda vez, gere somente os trechos/blocos completos, que tiverem alterações;

Quando o código alterado tiver comentários, seguindo as mesmas regras definidas para comentários, atualize os comentários existentes de acordo com as alterações, especialmente descrições de funções, remova comentários que passam a ser desnecessários e adicione novos caso seja pertinente;
